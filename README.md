# 教学智能体平台

微信小程序和网页是两个独立的客户端，均支持学生、教师两种身份。学生可以连续问答、督学、预习复习检测和提交作业，教师可以复核作业、查看班级错因、备课及撰写教案。两端共用一套 FastAPI 服务和数据库。当前检测与作业主题为异分母分数加法。教育资讯尚未实现。

| 目录 | 内容 | 发布方式 |
| --- | --- | --- |
| `wechat/` | 微信原生 TypeScript 小程序，学生与教师工作台 | 导入微信开发者工具并上传 |
| `web/` | Vue 3 + TypeScript 网页，学生与教师工作台 | 将 `web/dist/` 的内容上传静态网站托管 |
| `backend/` | 两个客户端共用的 Python API、成员身份和数据 | 部署一份服务，两个客户端配置相同的 API 地址 |

分开上线、账号关联和数据联调步骤见 [部署说明](DEPLOY.md)。`发布包/` 提供小程序导入包和网页静态包。

## 本地启动

此工作区已经安装了开发依赖。在这台电脑上，可直接在项目根目录的 PowerShell 启动演示服务：

```powershell
$env:PYTHONPATH = (Resolve-Path '.dev/python').Path
$env:DEMO_MODE = '1'
$env:GRADER_MODE = 'rules'
& "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe" -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### 在其他开发机上安装

在项目根目录的 PowerShell 使用 Python 3.11 或 3.12 执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
$env:DEMO_MODE = '1'
$env:GRADER_MODE = 'rules'
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

在微信开发者工具中导入 **wechat** 目录。项目预设测试 AppID（touristappid），若工具提示选择账号，可使用工具提供的测试号。本机模拟器调用 `http://127.0.0.1:8000/api` 时，在开发者工具的本地设置勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。开发者工具内置 TypeScript 编译，无需构建 npm 即可试用。正式发布或真机体验需换成实际 AppID，并在 `wechat/miniprogram/config.ts` 配置可达的 HTTPS 后端，在微信公众平台登记对应的 request 合法域名。

在另一个 PowerShell 窗口进入 `web/`，首次运行 `pnpm install`，再运行 `pnpm dev` 并打开终端显示的网址。Vite 将本地 `/api` 转发到端口 8000。正式静态部署的地址配置见部署说明。

### 试用顺序

1. 以示例学生进入，提交 `2/7`，应看到“已提交，等待教师反馈”。
2. 退出并以示例教师进入，刷新作业列表，打开“复核作答”。本地规则只比较分数与参考答案是否等值，未给出步骤时，具体错因由教师核实。
3. 选择“需订正”，填写给学生的反馈和用于统计的错因，点“确认并发给学生”。教师端按已复核作答统计错因及份数。
4. 切换回学生端，查看刚才确认的内容。未复核的草稿仅在教师端可见。

### 学习与备课试用

- **AI 老师**：从“我的学习”进入，问“为什么要通分”，再问“能举个例子吗”。最近 50 轮问答可以回看，模型模式会携带最近 8 轮上下文。每次回复显示来源。
- **学习督导**：输入自己的目标和 1 至 120 分钟的时长，可暂停、继续或结束。计时状态保存在后端，离开页面后返回会重新计算剩余时间。到时在督导页面内提醒。点“获取督学建议”可结合目标、剩余时间和本人最近一次检测的薄弱点获得下一步建议。此版本只记录学生主动设置的目标、时长和状态，不采集摄像头、麦克风或其他应用的行为，也不发送微信后台通知。
- **预习检测与复习检测**：两个入口分别检查分数单位、等值分数、通分概念，以及计算、辨错和情境运用。交卷后可核对所选答案、参考答案及讲解。各阶段分别保存结果，可回看最近 20 次，或重做同一组题。
- **备课与教案**：教师填写课题、授课对象、课时和教学目标，可主动勾选参考本班已确认的错因。先生成并编辑备课，再按当前文字生成教案，两份草稿都可修改和保存。“我的备课”仅展示当前教师在当前班级的作品。

## 存储与模型

单机试点使用 SQLite 文件 `learning.sqlite3`，无需单独安装数据库。设置 `DATABASE_PATH` 可以指定已有目录下的其他数据库文件。每次提交有独立请求编号，超时重试可复用编号。后台线程从数据库读取任务，临时中断的任务在租约到期后可继续处理。模型调用连续失败会进入人工批改。教师确认后的结果才会发给学生并计入本班错因汇总。

默认 `GRADER_MODE=rules` 为本地规则演示。启用模型批改时，在**后端进程**配置以下环境变量并重启：

| 变量 | 值 |
| --- | --- |
| GRADER_MODE | `model` |
| MODEL_ENDPOINT | 支持 chat completions 消息格式的完整 HTTPS 请求地址 |
| MODEL_NAME | 所选服务的模型标识 |
| MODEL_API_KEY | 所选服务的密钥 |

启用后会向指定服务发送试点题目和学生作答。先用示例数据验证返回格式与教师评判的一致性。缺少凭据、超时或输出格式错误时，教师可接手批改。

问答、督学建议、备课与教案共用以上模型服务配置。`TEACHING_MODE` 单独控制教学助手，未设置时沿用 `GRADER_MODE`。设为 `model` 时，会发送当前任务所需的问答上下文、学习目标与薄弱点，或教师输入与主动选择的错因。调用失败会提示重试。设为 `rules` 时显示“本地示例”：问答使用分数教学示例，督学建议按目标与检测结果组合，备课和教案按输入套用本地教学模板。预习复习检测始终由服务端按试点题库评分。

## 微信身份与班级

演示模式仅用于绑定本机回环地址的服务。两个示例身份共享固定演示班级，方便在一台设备上体验两端。实际登录由小程序调用 `wx.login`，后端换取 OpenID，用预先配置的成员名单决定角色和班级。

- 后端关闭演示入口（移除 `DEMO_MODE` 或设为 `0`），设置 `WX_APP_ID`、`WX_APP_SECRET`、`MEMBERS_FILE`。前端将 `DEMO_LOGIN` 设为 `false` 并使用同一小程序的真实 AppID。
- `MEMBERS_FILE` 指向后端私有 UTF-8 JSON 文件。以实际 OpenID 为键，值为 `{"role":"student","class_id":"class-a","name":"学生甲"}` 或相应的教师记录。当前试点按每个账号一个班级配置。变更班级或身份后，已有会话最长保留 24 小时，可从 sessions 表撤销。
- 密钥和成员名单仅放在服务器。学生只能读自己的提交，教师只能复核本班提交。服务端决定身份，客户端无法通过请求自行提升权限。
- 生产部署前需验证真实账号登录、HTTPS、模型质量、数据授权与保存策略，并按实际规模评估数据库和后台任务部署。

## 开发检查

```powershell
.\.venv\Scripts\python.exe -m unittest backend.test_flow backend.test_learning backend.test_web
cd wechat
npm install
npm run typecheck
```

后端测试启动隔离的 HTTP 服务并使用临时数据库，覆盖作业、问答上下文、两类检测、督学计时、教案生成与编辑、重试及跨身份访问。模型模式测试使用模拟响应。前端开发依赖用于静态类型检查。
